# Артефакты и протоколы проекта BanID

## 1. Введение

Документ содержит перечень основных артефактов проекта BanID и описание способов взаимодействия между его модулями. Он используется для фиксации структуры проекта, правил хранения файлов в Git и основных соглашений, применяемых при разработке.

## 3. Протоколы взаимодействия

### 3.1. Протокол навигации

**Участвующие модули:** Windows, Pages.  
**Назначение:** открытие и переключение страниц пользовательского интерфейса.

`MainWindow` открывает `LoginPage`. После успешной авторизации создаётся `DashboardWindow`, который в зависимости от роли пользователя загружает `UserDashboardPage` или `AdminDashboardPage`.

Для переходов между страницами используется механизм навигации WPF. Между компонентами передаются объекты C#, например `AuthUser`.

### 3.2. Протокол работы с данными

**Участвующие модули:** Pages, Services.  
**Назначение:** передача действий пользователя сервисному уровню и получение результатов обработки.

Страницы обращаются к `DatabaseService` через `App.Database` и используют его публичные методы:

- `Authenticate()`;
- `RegisterUser()`;
- `GetUserAccounts()`;
- `GetUserDeposits()`;
- `GetRequests()`;
- `GetAdminRequests()`;
- `AddUserRequest()`;
- `AddStatement()`;
- `ReviewRequest()`.

Данные передаются в виде обычных значений и объектов C#. Для обмена между модулями JSON и XML не используются.

### 3.3. Протокол работы сервисов с моделями и базой данных

**Участвующие модули:** Services, Models.  
**Назначение:** получение, добавление и изменение данных приложения.

`DatabaseService` использует модели данных и `BanIdContext`. Доступ к контексту выполняется через `App.Context`. Результаты операций возвращаются вызывающим страницам в виде объектов моделей.

### 3.4. Протокол обработки защищённых данных

**Участвующие компоненты:** DatabaseService, SecurityService.  
**Назначение:** обработка логинов, паролей и персональных данных.

Для этого используются методы `GenerateSalt()`, `HashPassword()`, `HashLogin()`, `NormalizePhone()`, `NormalizeLogin()`, `IsValidPassword()`, `EncryptPersonalData()` и `DecryptPersonalData()`.

### 3.5. События

Отдельный механизм событий для обмена между модулями не используется. В пользовательском интерфейсе применяются стандартные события WPF, например `Click` и `SelectionChanged`. Их обработчики вызывают соответствующие методы сервисов.

## 4. Соглашения об именовании и версионировании

В проекте используются следующие соглашения:

- классы и публичные методы записываются в стиле PascalCase;
- названия страниц заканчиваются на `Page`;
- названия окон заканчиваются на `Window`;
- названия сервисов заканчиваются на `Service`;
- пространства имён соответствуют структуре проекта: `BanID.Models`, `BanID.Services`, `BanID.Pages`, `BanID.Windows`;
- файлы `.xaml` и соответствующие `.xaml.cs` имеют одинаковое основное имя;
- названия обработчиков событий отражают действие и событие, например `Register_Click`.

В текущей версии проекта отдельная схема версионирования сборок и релизов не настроена. Для дальнейшего развития может использоваться версирование в формате `MAJOR.MINOR.PATCH`, например `1.0.0`.

Изменения исходного кода фиксируются в Git отдельными коммитами. Сообщение коммита должно кратко описывать выполненное изменение.

## 5. Заключение

В документе были собраны основные артефакты проекта BanID и описаны правила их хранения в Git. Также были зафиксированы основные протоколы взаимодействия между модулями Windows, Pages, Services и Models, а также соглашения об именовании и версионировании. Это позволяет использовать единое описание структуры проекта при дальнейшей разработке и интеграции его компонентов.
